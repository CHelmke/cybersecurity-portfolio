# Cybersecurity Incident Report

## Incident Type

DNS Service Availability / Network Communication Failure

## Status

Under Investigation

## Initial Observation

Approximately 1:24 PM

---

## Executive Summary

Several users reported that they were unable to access the company website and received a **destination port unreachable** error.

The issue was reproduced and network traffic was analyzed using `tcpdump`.

The packet capture showed that the client sent DNS queries over UDP to the DNS server on port 53. Instead of receiving DNS responses, the client received ICMP messages indicating that UDP port 53 was unreachable.

Because DNS resolution failed, the browser was unable to obtain the destination IP address required to continue connecting to the website.

---

## Network Evidence

### Expected Communication

A normal connection should begin with the browser requesting the IP address associated with the website's domain name.

```text
Client → DNS query → DNS server
DNS server → DNS response → Client
```

The browser can then use the returned IP address to initiate the website connection.

### Observed Communication

The packet capture instead showed:

```text
Client → UDP DNS query → DNS server:53
DNS server/network → ICMP "UDP port 53 unreachable" → Client
```

The ICMP error was observed repeatedly.

---

## Protocols Identified

### DNS

DNS translates domain names into IP addresses.

The browser needed to resolve the website's domain name before continuing the connection.

### UDP

The observed DNS queries were transmitted using UDP.

### ICMP

ICMP returned the error indicating that UDP port 53 was unreachable.

### Port 53

Port 53 is commonly associated with DNS services.

---

## Findings

The investigation established that:

- DNS queries were successfully generated by the client.
- The queries were sent to the DNS server using UDP.
- The destination port was UDP 53.
- A normal DNS response was not returned.
- ICMP instead reported that UDP port 53 was unreachable.
- The DNS lookup therefore failed.
- The browser could not obtain the IP address needed to continue connecting to the website.

---

## Suspected Root Cause

The most likely cause based on the current evidence is that the DNS service on UDP port 53 was unavailable or not listening for requests.

Possible underlying causes include:

- DNS service failure
- DNS server misconfiguration
- Firewall configuration blocking DNS traffic
- Network access-control rules
- Other DNS infrastructure problems

Additional investigation is required before confirming the root cause.

There is currently insufficient evidence to attribute the incident to malicious activity.

---

## Recommended Investigation Steps

The technical team should:

1. Verify that the DNS service is running.
2. Verify that UDP port 53 is listening.
3. Review DNS server configuration.
4. Review DNS server logs around the incident time.
5. Inspect firewall and access-control policies related to DNS traffic.
6. Verify connectivity between the client network and DNS server.
7. Retest DNS queries after remediation.
8. Confirm website accessibility once name resolution succeeds.

---

## Analyst Conclusion

The available packet evidence indicates that the immediate failure occurred during DNS resolution.

The client attempted to resolve the website's domain name through UDP port 53 but received ICMP port-unreachable responses instead of DNS responses.

The investigation should therefore focus first on the DNS service and the network controls surrounding UDP port 53.

Further evidence is required before determining the underlying reason the DNS service became unavailable.
